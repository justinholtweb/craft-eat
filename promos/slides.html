Delivery

Written, then
taken there

Every run writes the local file first, so a dead FTP server can never take the public feed URL down with it.

1A file, and a URL that stays putStaged and renamed into place, so a fetch mid-run gets yesterday’s feed, never half of today’s
2An asset volumeS3, Spaces, anything with a filesystem
3FTP or SFTPUploaded on every run, credentials from environment variables
4Google Merchant CenterContent API v2.1, in batches of 100 — no Google SDK

Or serve it live at /eat/feed/<handle>, cached for the schedule interval.

Schedule & console

One cron line,
every feed

Feeds regenerate on their own interval, in the queue — and on a product save, debounced, if you want the channel to know sooner.

$ php craft eat/feeds/generate --due
google-shopping   1,284 products, 12 skipped, 2.1 MB, 4.3s
meta-catalog      1,284 products, 12 skipped, 1.4 MB, 3.9s
tiktok-catalog    1,272 products, 24 skipped, 402 KB, 3.7s
$ php craft eat/feeds/preview google-shopping
5 rows, 12 skipped   missing:image_link: 12
$ php craft eat/feeds/export --file=feeds.json
4 feeds written to feeds.json
